# Project rules
- I am a non-technical beginner. Use plain language, one checkpoint at a time.
- Static HTML/CSS/JavaScript only. One index.html with styles and scripts included in it, no separate files. No frameworks, build steps, backend, accounts, or paid APIs.
- No outside downloads: no fonts, images, or code loaded from other websites. The game must work offline.
- The game must open by double-clicking index.html in a browser.
- Before changing files, tell me which repo, branch and files you will touch.
- Make only the next agreed increment. Preserve what already works.
- If something is unclear, or a request would break one of these rules, stop and ask me before doing it.

# Checking work
- Never claim a check passed unless you actually ran it. Say what you verified versus what I must check in my browser.
- After each change, give me numbered steps to try in my browser and what I should see.
- Record test results as Passed, Failed, or Not tested in test-report.md.

# Explaining and saving
- After each change, give me a 2-3 sentence plain-language summary of what changed and why.
- After each checkpoint, commit with a clear message and push only to the agreed branch. Never open a pull request unless I ask.
- If something breaks, tell me plainly and offer to go back to the last working version.

# Game quality
- Readable text size, enough color contrast, and the game playable with the keyboard as well as the mouse.
- The board must fit and work on a phone screen.

# Project files
- Keep game-brief.md and project-state.md current.
- If game-brief.md, project-state.md, or test-report.md don't exist yet, create them at the next checkpoint instead of skipping them.
